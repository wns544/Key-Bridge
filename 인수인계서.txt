## 3. 큰 작업 흐름 요약

### 3.1 마우스/포인터 문제

- 최초 문제: iPad 연결 직후 마우스 커서가 중앙으로 갔다가 좌상단으로 튕기는 현상.
- 원인 후보: 연결 직후 상대좌표 마우스 리포트가 과하게 들어가거나 iPad가 포인터 초기 위치를 캐시/보정하는 문제.
- 브랜치: `codex/absolute-pointer-hid`
- 구현 방향:
  - 절대좌표 HID 리포트를 추가해서 연결 직후 중앙 위치를 한 번 보냄.
  - 이후 실제 이동/클릭/휠은 기존 상대좌표 마우스 리포트로 처리.
- 중간 버그:
  - 절대좌표 HID에 버튼까지 실으면 클릭이 드래그처럼 홀딩되는 문제가 있었음.
  - 해결: 절대좌표 리포트는 버튼 없는 위치 보정 전용으로만 사용하고, 클릭/드래그는 상대좌표 마우스 리포트로만 처리.
- 관련 파일:
  - `Services/BluetoothHidBridgeService.cs`
  - `Services/IHidBridgeService.cs`
  - `Services/SimulatedHidBridgeService.cs`

### 3.2 클립보드 텍스트 입력

- 목표: Windows 클립보드의 텍스트를 iPad에 HID 키보드 입력으로 보내기.
- 기본 입력:
  - `F3`: 영문/숫자/기본 기호 빠른 입력.
- 스마트 입력:
  - `Ctrl+Shift+V`: 한영 혼합 스마트 입력.
  - iPad 입력 상태는 기본적으로 한글이라고 가정하는 방향으로 조정했음.
  - 한글 음절은 두벌식 키 시퀀스로 분해해서 입력.
  - 영어 구간과 한글 구간 사이에서 `Ctrl+Space`로 iPad 입력소스를 전환.
- 취소:
  - `Esc`: 진행 중인 클립보드 입력 취소.
  - `Ctrl+Esc`: 브릿지 긴급 중지.
- 관련 파일:
  - `MainWindow.xaml.cs`
  - `Services/GlobalInputHookService.cs`
  - `Services/HidKeyboardReport.cs`

### 3.3 한글/영문 입력 상태 관련 한계

- BLE HID만으로는 iPad의 현재 입력 언어 상태가 한글/영어/일본어인지 읽어올 수 없음.
- iPad는 HID 장치 쪽으로 현재 입력소스 상태를 표준적으로 알려주지 않음.
- 그래서 현재 방식은 “초기 상태를 가정하고 전환 횟수를 관리”하는 방식임.
- 현재 사용 규칙:
  - `Ctrl+Shift+V` 사용 전 iPad 입력기를 한글 상태로 맞추는 것이 가장 안정적.
- 일본어 입력기가 끼면 `Ctrl+Space` 순환 순서가 꼬일 수 있음. 이 경우 완전 자동 판별은 어려움.

### 3.4 특수문자 정규화

- HID 키보드로 직접 칠 수 없는 유니코드 문자를 ASCII 대체 문자열로 바꾸는 로직을 추가.
- 예:
  - `α -> alpha`
  - `β -> beta`
  - `π -> pi`
  - `≤ -> <=`
  - `≥ -> >=`
  - `≠ -> !=`
  - `≈ -> ~=`
  - `± -> +/-`
  - `× -> x`
  - `÷ -> /`
  - `√ -> sqrt`
  - `∞ -> infinity`
  - `² -> ^2`
  - `₁ -> _1`
  - `½ -> 1/2`
  - `→ -> ->`
  - 스마트 따옴표는 일반 따옴표로 변환.
- 주의:
  - 기존 `NormalizeClipboardTextForHidTyping` 함수는 콘솔 인코딩 문제로 문자열이 깨져 보였음.
  - 새로 `NormalizeClipboardTextForHidTypingSafe` 함수를 추가하고 호출부를 새 함수로 돌렸음.
- 이 변경은 로컬에만 있고 아직 GitHub에 푸시되지 않았을 가능성이 큼.

### 3.5 GoodNotes 자동 번호 목록 방지

- GoodNotes에서 줄 시작 `1.`, `2.` 같은 패턴을 자동 번호 목록으로 바꾸며 들여쓰기되는 문제가 있었음.
- 스마트 입력 시 줄 시작 숫자 목록 패턴을 `1)` 형태로 바꿔 자동 목록 트리거를 피하도록 처리.
- 관련 함수:
  - `PreventGoodNotesAutoNumberedLists`
  - `ReplaceLeadingNumberedListMarker`

### 3.6 Ctrl 편집/이동 단축키 복구

- 문제:
  - `Ctrl+Backspace`, `Ctrl+Left/Right`가 사용자가 기대한 방식대로 동작하지 않았음.
- 원인:
  - `GetModifier()`에서 Windows `Ctrl`을 iPad용 `Command`로 바꾸는데, 특수 매핑 판별도 그 변환된 값을 보고 있어서 “Ctrl이 눌렸는지”를 못 알아봄.
- 해결:
  - `IsControlKey` 헬퍼를 추가해 원본 Windows Ctrl 키코드 기준으로 판별.
- 의도된 매핑:
  - `Ctrl + Left/Right -> iPad Option + Left/Right`
  - `Ctrl + Shift + Left/Right -> iPad Option + Shift + Left/Right`
  - `Ctrl + Backspace -> iPad Option + Backspace`
  - `Ctrl + Delete -> iPad Option + Delete`
- 관련 파일:
  - `Services/HidKeyboardReport.cs`

### 3.7 Excel Shift+F3 충돌

- 문제:
  - Excel에서 `Shift+F3`를 누르려는데 KeyBridge가 `F3` 클립보드 입력으로 먹어버림.
- 원인:
  - `F3` 핫키 조건이 modifier 여부와 무관하게 “F3이면 무조건”으로 되어 있었음.
- 해결:
  - `F3`은 Ctrl/Alt/Shift가 모두 안 눌린 순수 `F3`일 때만 KeyBridge가 잡도록 변경.
  - `F4`도 modifier 없는 순수 `F4`일 때만 이미지 공유로 잡도록 변경.
- 관련 파일:
  - `Services/GlobalInputHookService.cs`
- 이 변경은 로컬에만 있고 아직 GitHub에 푸시되지 않았을 가능성이 큼.

### 3.8 이미지 공유/스크린샷 공유

- 관련 파일:

- UI에 버튼 추가:
  - `Screenshot`

- 단축키:

  - `Ctrl+Alt+I`: 이미지 공유 fallback.
- 동작:

## 4. 현재 단축키 현황

- `F4`: 클립보드 이미지 공유. 단, Ctrl/Alt/Shift 없이 순수 F4일 때만.
- `Ctrl+Alt+I`: 이미지 공유 fallback.
- `Ctrl+Alt+E`: iPad 입력 선택/이모지 선택용 `Ctrl+Space` 전송.

## 6. 최근 중요 빌드/실행 명령

빌드:

```powershell
dotnet build
```

배포 EXE 생성:

```powershell
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o .\dist\publish-temp
Copy-Item -LiteralPath .\dist\publish-temp\KeyBridge.exe -Destination .\dist\KeyBridge.exe -Force
Copy-Item -LiteralPath .\dist\KeyBridge.exe -Destination "$env:LOCALAPPDATA\Programs\KeyBridge\KeyBridge.exe" -Force
Remove-Item -LiteralPath .\dist\publish-temp -Recurse -Force
```

실행:

```powershell
Start-Process -FilePath "$env:LOCALAPPDATA\Programs\KeyBridge\KeyBridge.exe"
```

아이콘 재생성:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Create-AppIcon.ps1
```

## 8. 사용자 성향/작업 방식 메모

- 사용자는 한국어로 빠르게 피드백하며, 실제 iPad/GoodNotes에서 바로 테스트한다.

- GitHub에 푸시된 버전과 로컬 설치본 버전이 달라질 수 있으므로, 항상 `git status`, `git log`, 설치 EXE 경로를 함께 확인하는 것이 좋다.
